# 구현 지시서

Codex는 작업 중에 프로젝트의 진입 문서(`AGENTS.md` 등)도 읽는다. 프로젝트가 "승인 전에는 구현하지 않는다" 같은 단계 규칙을 두면, Codex가 멈추거나 계획을 다시 세우려 할 수 있다. 그래서 지시서 첫머리에 승인 사실과 지금 단계를 밝힌다.

## 양식

```
# 작업: <한 줄 제목>

## 지금 단계
이 작업의 구현 계획은 개발자가 이미 승인했다. 너는 구현 단계다.
계획을 다시 세우거나 승인을 다시 받지 않는다.

## 승인된 계획
<계획 전문, 또는 이 작업에 해당하는 부분>

## 고쳐도 되는 파일
- <경로> (새로 만들 파일 포함)
이 밖의 파일은 고치지 않는다. 꼭 고쳐야 하면 멈추고 묻는다.

## 따를 프로젝트 규칙
- <읽을 스킬 문서 경로> — 처음부터 끝까지 읽고 필수 규칙을 지킨다.

## 완료 기준
- <동작 기준>
- <실행할 테스트 명령 — 단위 테스트만>

## 묻고 기다릴 것
아래가 필요하면 짐작하지 말고 질문하고 답을 기다린다.
- 계획에 없는 동작, 예외 처리, API 응답, 데이터 구조, 화면 문구
- 고쳐도 되는 파일 밖의 변경
- 계획과 코드가 맞지 않는 곳
- 프로젝트 규칙을 지킬 수 없는 곳

## 하지 않을 것
- 커밋, push, 브랜치 변경
- 데이터베이스·운영 환경 접근, 공유 자원을 쓰는 테스트(통합·DB 테스트)
- 개발 서버 띄우기
- 계획 밖 리팩터링

## 끝나면 보고할 것
- 바뀐 파일 목록
- 돌린 테스트와 결과
- 남은 일, 짐작한 곳(있다면)
```

## 쓸 때 주의

- 고쳐도 되는 파일은 경로로 적는다. "관련 파일" 같은 말은 짐작을 부른다.
- 작업을 나눴다면 지시서끼리 파일이 겹치지 않게 한다. 겹치면 순서대로 돌린다.
- 화면 작업이면 개발자가 준 시안·스크린샷을 파일로 저장해 경로를 적는다.
- 지시서는 구현 계획 단계에서 Codex 점검을 받는다([opinion.md](opinion.md)).
